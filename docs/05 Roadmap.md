# 05 Roadmap

Each milestone ends with a demo on a real device and a short retro: what new needs appeared → update [[01 Brainstorm]] and [[06 Task Backlog]].

| Milestone | Goal | Outcome | Tasks |
|-----------|------|---------|-------|
| **M0 — Environment & skeleton** | Toolchain works, empty app runs on Windows and in Chrome, Android APK builds | `flutter doctor` clean, project with lint, folder structure, git | T-001 … T-006 |
| **M1 — Domain core** | The planner exists and is proven by tests | `LocalDate`, `Task`, `Settings`, `Planner` (forcing, overflow, urgency boost, pins, Focus view) with the full test table from [[04 Planner Algorithm]] | T-101 … T-111 (T-111 added 2026-11-13: Focus replaces the Today queue) |

| **M5 — Polish & release (v0.3)** | Something you would keep installed | Notification, backup, icon, tests, signed release build | T-501 … T-506 |

| **M9 — Redesign (v0.5)** | The new look of the owner's mockups, the logic unchanged | Theme tokens for light and dark, a shared task card with a Done button, done tasks kept in sight, a tap opens the task menu, Today with a progress bar, Plan with capacity pills and free slots, Tasks with "Active" and counters on the filters; a done task stays on its plan day (schema 4, backup format 4) (D22, ADR-23) | T-901 … T-907 |
| **M10 — Allowed days (v0.7)** | A task that can only be done on some days of the week is planned only there, and moves on by itself when the day is missed | `Task.allowedWeekdays`, the planner's day test in the fill, the overflow and forcing (forcing counts only the allowed days), a pin in the past goes to the nearest allowed day, a "Days" row in the editor, a chip on the card, schema 6, backup format 6 (D23, ADR-25) | T-1001 … T-1006 |
| **M11 — Tuning (v0.8)** | Small changes from daily use, the logic unchanged | The right swipe on Tasks pins a task to its planned day, quick add can pin to today and open the full editor, the "quiet card" v2 (title first, neutral chips with a priority dot) | T-1101 … T-1104 |

M10 was designed on 2026-11-16 (brainstorm with the owner) and built on 2026-11-16 … 17 (0.7.0). M11 was planned and built on 2026-11-17 (0.8.0).

M7 was designed on 2026-11-14 and does not depend on the open tasks of M5 or on the widget (T-601); the owner picks the order. M8 was designed the same day and comes after M7 (owner): both change the same parts of the planner. M9 was designed on 2026-11-15 and is **done before M8** (owner): M8 adds a size to the task card and a load to the day headers, so it is built in the new look from the start. The numbers stay in the order the milestones were planned; M9 is v0.5 and M8 moves to v0.6.

## Suggested order inside the cycle
1. Pick the next unchecked task in [[06 Task Backlog]] (respect `depends`).
2. Write/adjust the test first when the task is domain or data.
3. Implement, run `flutter analyze` and `flutter test`.
4. Tick the task, note anything learned in the task's "Notes" line.
5. At milestone end: device demo, update docs, groom the backlog.

## Risks
- **Toolchain on Windows** (Android SDK licences, JDK version, emulator): time-box T-001 to one evening; a physical phone with USB debugging avoids the emulator.
- **Codegen friction** (`build_runner` for drift/freezed/riverpod): set up a `tool/gen.sh` / VS Code task early (T-003).
- **Planner edge cases**: keep the test table as the contract; every bug found in the UI becomes a new row before it is fixed.
- **Scope creep**: parking lot in [[01 Brainstorm]] exists for a reason.

### M10 — 2026-11-17 (allowed days, 0.7.0)
- **Done:** T-1001 … T-1006. `Task.allowedWeekdays` with `allowsDay` and `setAllowedWeekdays`; the planner places such a task only on its days (fill, top-level overflow, forced picks), a pin in the past goes to the nearest allowed day, forcing has a check per set of days (and per heavy weight inside a set) with the cut to what can be done today; schema 6 and backup format 6; the "Days" row in the editor with its sheet and quiet hints, the "Only Sat" chip. 852 tests. Release 0.7.0+14.
- **Demo:** emulator, release APK over 0.6.0+13 with the two tasks on it (schema 5 → 6 kept them and their days in the plan). "Papery" Thu, Fri: on Thursday, after a missed Thursday on Friday, after a missed Friday on the next Thursday, never in Focus. "Tyres" Low, only Sat, due Mon 30 with six High "only Sat" tasks: Sat 21 went to three High tasks, on Sat 28 Tyres came first with "Deadline" and pushed the sixth High one to Dec 5; after the date it was in Focus, overdue, on a later Saturday. - **New backlog items (parking lot):** a share of the slots per priority level against starvation; places with opening days shared by several tasks.
- **Learned:** `adb shell input text` types only Latin letters, so the walkthrough tasks had English names; a drift row compares a `Set` column by identity, so a schema test compares such a row field by field.

Release 0.6.0+13.

- **Learned:** sorting the pool on every day made the planner slower than its 50 ms budget with 20 daily series (scenario 33); the top-level check runs only on a day smaller than the heaviest task, and the pool is sorted only when the fill or that check needs it. uiautomator gives a card its chips and title as one label with line breaks, and a hint that starts with a segment's name ("Small: two share…") catches a prefix match: match the exact label first.
